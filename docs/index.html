讓每一次練習，
都像面對真實的客戶。

SkillCoach 是基於多模態 Agent 的企業與教育全情境模擬培訓平台：以情境擬真與動態引導智能體對練，接上擬真語音與情緒交互、企業知識庫 RAG，並用科學化評估把「訓練成效」變成看得見的數據。

Pain Points

產業痛點

企業與教育現場的培訓，卡在四個結構性問題。

企業培訓困難

角色扮演與實戰演練高度依賴資深人員陪練，成本高、排程難、難以規模化。

企業知識傳遞

產品知識、SOP 與經驗散落在文件與資深員工腦中，隨人員流動而流失。

填鴨式學習成效不彰

固定腳本與單向講授，學員背得起來卻用不出來，面對真實情境仍然生疏。

傳統 Agent 皆為一問一答

既有 AI 助理只能被動應答，無法主導情境、引導學習，也不會評估表現。

Innovation

創新

Dynamic Scenario Agent

情境擬真與動態引導智能體

不是一問一答的聊天機器人，而是能主導情境、隨學員表現動態調整劇本與難度、主動引導的智能體。

Knowledge Reuse

企業知識庫再利用

把企業既有的文件、SOP、FAQ 直接轉化為訓練情境與標準答案，讓沉睡的知識庫成為培訓資產。

Personalized & Scientific

個人化學習與科學化評估

依每位學員的弱點調整訓練路徑，並以可量化、可追溯的評估準則取代主觀印象打分。

Core Features

四個模組，組成一位不會累的教練

01 / ROLE-PLAY

自適應角色扮演

AI 扮演客戶、病患或面試官，依學員回應即時調整態度、難度與情境分支，避免「背答案」式訓練。

02 / VOICE + AVATAR

即時語音與 3D 虛擬人

串流語音辨識與合成，搭配口型同步的 3D Avatar，讓對練有真人般的語氣、停頓與表情壓力。

03 / ENTERPRISE RAG

企業知識 RAG

匯入產品手冊、SOP、FAQ 等文件，AI 對手的問題與標準答案皆引用企業知識庫，確保內容正確且可更新。

04 / EVALUATION

實證績效評估

依可設定的評分準則（rubric）逐句分析對話，每個分數都附上原話證據與改進建議，主管與學員看到同一份事實。

選擇情境

從情境庫挑選或由 HR 依知識庫自動生成任務。

語音對練

與 3D 虛擬客戶即時對話，AI 依表現動態調整。

知識檢索

AI 回應與追問全程引用企業文件。

逐句評估

依 rubric 產出分數、證據與建議。

追蹤成長

個人與團隊儀表板呈現趨勢與弱點。

Engineering

核心技術

以下每一點都能在原始碼裡逐行對應。

01 / ORCHESTRATION

七階段 Multi-Agent 編排

每輪對話由對話編排器依序呼叫七個責任明確的 Agent，而不是單一個大 prompt 硬撐全場。

  • 合規預檢 → 情境導演 → 知識檢索 → 客戶模擬（串流回覆）→ 合規複檢 → 教練回饋 → 評分
  • 情境導演的難度升降是決定性規則引擎，不呼叫 LLM；訓練模式可降難度，正式評測模式禁止自動降難度，避免評分被灌水
  • 客戶模擬以信任、興趣、抗拒、耐心等狀態變數驅動語氣與立場，並有程式化守門機制防止角色扮演洩漏隱藏設定
  • 非關鍵環節（如教練回饋）失敗時自動降級，不會讓整場對話中斷
02 / SCORING

逐字核對證據，拒絕幻覺分數

評估引擎不是讓 LLM 憑印象打分，而是把「證據」當成程式碼可以驗證的物件。

  • 模型每個分數都必須附上引用逐字稿的原話證據
  • 系統逐字核對該引用是否真的出現在逐字稿中，核對不上的證據直接捨棄
  • 證據不足時強制打中性分數（45–55），而非放任模型自由心證
  • 內建 10 個技能維度的評分標準，訓練模式與正式評測模式套用不同難度規則
03 / HYBRID RAG

七種切塊策略 + 混合檢索

完整 parse → chunk → embed → index → retrieve → rerank 管線，而非把文件整份塞給 LLM。

  • 切塊策略依文件型態自動選用：標題、段落、固定 token、語意、表格、FAQ、自動判斷共七種
  • 向量資料庫採 Qdrant，並以租戶隔離參數強制過濾，避免跨企業知識庫互相查到彼此資料
  • 檢索採 RRF（倒數排名融合）混合向量與關鍵字搜尋，而非單純比對向量相似度
  • Embedding 雙軌支援：可用私有部署模型（BGE / e5）或 API（OpenAI），依企業資安需求選擇
04 / AVATAR FALLBACK

依硬體效能自動降級

虛擬人渲染不是單一模型賭運氣，而是一條會自己判斷硬體能力的渲染鏈。

  • 表情與頭部姿態由 LivePortrait 驅動、嘴型由 MuseTalk 驅動
  • 效能不足時自動降級：MuseTalk → Wav2Lip → 純音量驅動嘴型，確保不同硬體都能即時運作而不卡格
  • 表情轉換加入遲滯（hysteresis）機制，避免情緒在臨界值附近來回抖動
  • 畫面透過 WebSocket 逐幀傳輸（JPEG / WebP / PNG）
Affect Sensing

情緒感知：雙路並行

兩個系統同時在讀學員的狀態，但它們可信度不同，所以融合方式是刻意不對稱的。

Text · auditable

文字：可稽核

讀學員這一輪實際說出口的話，並且必須引用逐字原話。伺服器端有四條驗證，全部由程式檢查而非交給模型自律：

  1. 引用必須逐字出現在這一輪學員的發言裡
  2. 要給明確標籤，就得同時有引用與真實強度
  3. 「不明確」不得挾帶強度
  4. 違反任一條，一律拒絕而非修補

被拒絕的結果是降級為「不明確」，不是丟出例外——情緒是加值訊號，不該讓一輪對話失敗。

Face · advisory

臉部：僅供參考

瀏覽器端跑 FaceLandmarker（WASM），52 個 blendshape 在使用者機器上算完，攝影機影格完全不離開本機。

  1. 分類規則移植自本專案的 emotion_webcam，是逐字翻譯而非重新詮釋
  2. WASM 與模型 vendored 到自家網域——CSP 只列自家來源，從 CDN 抓會被靜默擋掉
  3. 模型在第一次開啟攝影機時才懶載入
  4. 低於 0.45 信心就視為「臉沒說出什麼有用的東西」

融合：純算術，不再問模型

情況結果
兩邊都沒有證據回「不明確」，不預設「平穩」——平穩也是一種主張，沒有證據的主張比沉默更糟
只有文字說話採用文字，信心 = 強度權重 × 0.85
只有臉說話採用臉，但強度固定為 low、信心上限 0.6——沒有引用撐腰的讀數不該看起來跟有證據的一樣確定
兩邊一致提高信心
兩邊真的衝突文字勝出，並記錄衝突，不做平均
平均出來的標籤「會是唯一一個沒有人能在檢討會上為它辯護的東西」；而「叫模型去調解兩個標籤，它只會發明第三個」。所以融合寫成純算術，不再呼叫第二次模型，輸出同時帶著融合結果與兩邊的原始輸入，事後檢討看得到推導過程而不只是一個結論。

應用：即時教練提示

當負向情緒的信心 ≥ 0.55 且持續 1.5 秒，畫面就在對話區旁邊浮出提示卡主動提供協助——不是等到對練結束才在報告裡告訴學員「你剛才看起來很挫折」。

Avatar

虛擬人角色與表情驅動

「模型輸出動畫參數、Web 負責 3D 渲染」這條路線的實作：52 維 ARKit blendshape 係數 → morph target → 3D 角色。純前端，離線可跑。

角色素材

角色來自 Microsoft Rocketbox（MIT 授權，可商用）。4 個底模搭配年齡變體組成 8 個練習對象，涵蓋 20／30／40／50／65 歲、男女各半。每個角色帶 175 個 blendshape，其中 AK_* 開頭的 52 個就是完整的 ARKit 52，動畫資料可以原封驅動。

老化管線

年齡差異不是執行期調色，而是事先烤好的臉部與髮片貼圖：皺紋由老化 GAN 產生，白髮由亮度遮罩推出。關鍵是只取 delta（aged − original）疊回原貼圖，而不是整張換掉——delta 才是老化特徵，原本的五官與光影因此全部保留。

表情驅動

同一個角色、同一份 morph target，只改 52 維係數的結果。驅動分三層疊加：口型層做幀間線性插值並保留平滑包絡避免逐音節抽搐；情緒層在說話時仍保留 35% 權重，讓情緒的嘴角形狀在講話過程中依然可辨識；Idle 層負責 procedural 眨眼、眼球 saccade 與頭部微動。

骨架與動作

角色是綁好骨架的完整人體，不是只有一顆會動的頭。

Retarget

Mixamo 動作即時重定向

點擊後即時 retarget 到角色骨架播放，切換動作以 0.3 秒 crossfade 銜接。骨骼名稱對應表同時涵蓋 Mixamo 與 3ds Max Biped 命名，25 根關鍵骨骼全數命中。

Virtual T-pose

A-pose 與 T-pose 的 rest 差異

角色綁定姿勢是 A-pose，Mixamo 動作卻是相對 T-pose 記錄的，直接套會讓手臂多轉一次。逐骨骼求出把目標 rest 轉到來源 rest 的最小旋轉後，關節誤差降到 0.000002°。

Two-bone IK

雙骨 IK 修正

兩套骨架的肩膀階層與臂長不同，雙手靠近的動作（例如握手）會對不齊，改以逐幀取樣加 IK 修正。

Compliance

合規審查

對練中若出現禁止話術，系統會在當下標記，並附上禁止的理由、逐字稿佐證與建議改法。

Flagged

「保證保本」當場攔截

學員說出「這個保證保本，你完全不用擔心。」，系統立刻標記為不實承諾／重大風險，說明投資型保單不保證本金、帳戶價值可能低於已繳保費，並引用該句逐字原話為佐證，再給出可以照著說的改法。

Not flagged

正確劃清界線不會被標記

同一段對談前半，學員被問到稅務時回答「稅務我不能給建議，請以會計師或稅務專業意見為準」——合規檢查針對的是逾越界線的話術，不是禁止談論某個主題。

Progress

分數累積成學員進度

單場對練的評分不只停在報告，會累積成學員的長期進度。

Ten dimensions

十項維度各有及格線

及格線 80，每一分都能追到逐字稿佐證，並與團隊平均對照指出最擅長與待加強的維度。

Gate

合規是關卡型維度

出現重大發現即不通過，不會被其他維度的高分平均掉——上圖那場 68 分的練習就是因為 2 個合規旗標而未通過。

Vision & Impact

產品願景與影響力

產品願景

  1. 運用多模態導引達到具有溫度的 Agent 引擎不只是答對，而是能感受、引導、陪伴學習的智能體。
  2. 釋放企業知識庫價值讓沉睡在文件裡的知識，成為每位員工都能練習與內化的資產。
  3. 個性化教學引導依每個人的節奏與弱點，給出不同的路徑與回饋。

影響力

  1. 降低人才培育斷層新人不再只能等資深同事有空，隨時可練、隨時有回饋。
  2. 知識民主化、企業化專家經驗從少數人腦中，變成組織共同可用的訓練資源。
  3. 傳遞保留企業知識力人員流動不再等於知識流失，經驗被結構化保存並持續傳承。
